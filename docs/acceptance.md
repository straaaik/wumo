# Приёмка PixelThumbs

Функциональный прогон проведён на Windows 11 x64, сборка 26200, с .NET 10 Desktop Runtime. Исходная Release-сборка сохранена в каталоге артефактов для сравнения. Дизайн-файл PixelThumbs ожидается отдельно.

| Пункт ТЗ | Изменение | Проверка и результат |
| --- | --- | --- |
| 1. Интерфейс | Главное окно без стандартной рамки, отдельный раздел «Настройки», размер окна предпросмотра и автозапуск. Сохранены поиск, флажки и редактор общего и индивидуальных стилей. | Из Release проверены запуск, настройки, отмена и смена назначения, сохранение размера, сворачивание и перетаскивание между альбомным монитором 125% и портретным монитором 100%. Для финальной сверки оформления нужен дизайн-файл. |
| 2. Быстрый просмотр | Пробел использует выделение Проводника и список форматов PixelThumbs. Для других назначенных кнопок сохраняется нативное определение файла под курсором. Если изображение файла из списка недоступно, окно показывает свойства и причину. | На Windows 11 проверены разные выделенный файл и файл под курсором, отсутствие выделения и папка. Повреждённый и пустой STL дают карточку с причиной. Валидные ASCII и бинарный STL дают изображение. Для EXE, MOV, JPEG и TXT окно остаётся закрытым. |
| 3. Поставка F3D | Портативный F3D 4.0.1 с OCCT, Assimp, OSMesa, библиотеками и лицензиями. Путь берётся из поставки при любом значении прежнего поля в профиле. | Сверен SHA-256 официального архива. Для STEP, STP, IGES, IGS и FBX из готового пакета получены изображения 512×512. Все пять форматов прошли быстрый просмотр со старым нерабочим путём. Нативный COM-хост проверен в публикуемом пакете и в копии, собранной системной процедурой в изолированной папке. Для проверки на чистой машине нужен отдельный образ Windows. |
| 4. Применение и эскизы | Сканирование рабочего стола заменено подтверждаемым вызовом штатного обработчика категории «Эскизы». Есть сохранение без очистки и повтор при ошибке. | На Windows 11 вызов системного обработчика в режиме чтения оценил кэш в 9 467 016 байт. Полный сброс и повторное создание STL и STEP в двух папках требуют тестового профиля, где можно очистить весь кэш. Для проверки Windows 10 нужен доступ к такой системе. |
| 5. Настройки и регистрация | Откат значений реестра при ошибке, атомарная замена файла настроек, учёт системной регистрации по профилям. | В изолированных ветках реестра воспроизведена частичная запись в исходной версии. В Release прошли сценарии ошибки после записи, ошибки сохранения, повторного применения, обновления, восстановления прежнего обработчика и снятия регистрации двух профилей. Проверка полного жизненного цикла в обычном и системном Проводнике остаётся открытой. |
| 6. Значок на миниатюре | Удалена растровая отрисовка значка приложения. Подавление системного TypeOverlay задаётся для подключённого формата. | Исходный тест показал, что значок был частью растра. Проверки реестра подтвердили сохранность UserChoice, ProgID, команды открытия и восстановление прежнего TypeOverlay. Визуальная проверка в Проводнике с назначенным OrcaSlicer и реальным двойным щелчком по STL, STEP и STP остаётся открытой. |
| 7. Отрисовка и чтение | Убрано выборочное отбрасывание граней STL. Для плотных моделей снижается внутреннее разрешение и упрощаются эквивалентные грани. Для OBJ и PLY исправлена триангуляция вогнутых граней. Для G-code сравниваются кандидаты из начала и конца в пределах 2 МиБ чтения. | Исходная версия заполняла вырезы OBJ и PLY, выбирала меньший эскиз G-code и пропускала грани крупного STL. Прошли 10 проверок напрямую и 10 через worker, включая сравнение с эталоном, повреждённый блок, отсутствующий эскиз и случаи с обрезанными строками. При 512×512 проверены синтетические STL с 165 904 и 1 394 400 гранями и реальный STL с 2 435 933 гранями. Для проверки исходного STL на 165 904 грани нужен сам файл. |
| 8. Безопасность и скорость | Worker допускается к модели после настройки Job Object. F3D запускается из поставки и попадает в тот же Job Object. Диагностика различает ошибку чтения, отсутствие эскиза, F3D, таймаут и лимиты. Быстрый просмотр использует кэш до 16 МиБ по версии файла, стилю и размеру. | Проверены ограничение памяти Windows, отказ подключения Job Object до чтения файла, завершение worker по таймауту, отмена с остановкой worker и F3D, а также нормальные и повреждённые входные файлы. Кэш быстрого просмотра измерен в Проводнике. Сравнение заполнения папки с холодным и тёплым системным кэшем требует полного прогона Проводника в тестовом профиле. |

## Замеры на Windows 11

- Реальный STL на 2 435 933 грани в размере 512×512 занял 1,21 с на исходном worker и 1,54 с в одном сравнительном прогоне после исправления. В новой версии запуск и подключение Job Object заняли 7,7 мс, передача и предварительное чтение 1051 мс, второй проход и отрисовка 292 мс. Пиковая выделенная память Job Object составила 27,7 МиБ.
- В двух заключительных прогонах пробел показал уже отрисованный выделенный STL при 16 из 16 нажатий сразу после движения курсора. Максимум в этом сценарии составил 44 мс.
- В заключительном прогоне 512×512 тёплые CAD и FBX заняли 0,68–0,74 с с пиком 184–191 МиБ на Job Object. Первый запуск STEP занял 4,20 с. В статистике worker для F3D чтение измеряет передачу входа, а время внешнего рендера включает импорт модели и запуск F3D.

## Проверка производительности

Замеры на Windows 11 выполнены на одном компьютере и одних файлах. Для рендера указаны медианы пяти запусков.

| Сценарий | До оптимизации | После оптимизации |
| --- | --- | --- |
| Таймер в простое за три секунды | 65 срабатываний для пробела, 64 для боковой кнопки | 0 для обоих назначений |
| STL на 2 435 933 грани, 512×512 | 846 мс и 27,1 МиБ пиковой выделенной памяти Job Object | 803 мс и 12,9 МиБ |
| STEP 512×512, сравнение режимов F3D | 730 мс с программным OSMesa | 490 мс с автовыбором в окне просмотра |

Предпросмотр в настройках отменяет устаревший рендер при изменениях и уходит в ожидание при потере фокуса. Пиксели передаются в WPF без промежуточного PNG. Проверки подтвердили сохранность цвета, прозрачности и ориентации, отмену без ожидания на потоке интерфейса и обновление кэша при замене файла.

После оптимизации прошли 16 из 16 нажатий пробела сразу после движения курсора, максимум в этом сценарии составил 41 мс. В Проводнике также проверены выбор файла, карточки ошибок для поддерживаемых форматов, закрытие при отпускании, боковая кнопка, вкладки и предпросмотр всех пяти форматов F3D. Для миниатюр Проводника действует программный OSMesa. В окне просмотра F3D выбирает бэкенд по доступному драйверу. [Бэкенды F3D в Windows](https://f3d.app/docs/user/DESKTOP_INTEGRATION/#rendering-backends)

## Аудит фоновой нагрузки Wumo

- Для быстрого просмотра по пробелу используется только перехват клавиатуры. Другие назначения определяют файл под указателем асинхронно. Обработчик глобального ввода сразу возвращает управление Windows, пока нет подтверждённого файла. Отключение быстрого просмотра освобождает перехват и кэш изображений.
- Скрытие вкладки, сворачивание окна и потеря фокуса останавливают предпросмотр настроек и освобождают его процесс. На открытой вкладке процесс разбора модели завершается после 15 секунд без рендера.
- При выключении истории Wumo закрывает окно и поток захвата, снимает подписки и освобождает собственные ссылки на записи. Системный буфер сохраняет уже опубликованные данные. Шифрованная история объединяет изменения с задержкой 1,5 секунды. Превью 32-битного DIB V5 с обычными масками sRGB готовится из исходных пикселей с сохранением альфа-канала.
- В Windows 11 прошли проверки истории и DPAPI, выбора моделей в Проводнике, изображений предпросмотра и отмены, регистрации, нативных COM-миниатюр, STL, CAD и FBX. Проверены лимит памяти и остановка процесса рендера по таймауту и отмене. Тест кнопки перезапуска подтвердил сохранность черновика, отказ при повреждённом пакете и применение исправной сборки. Сквозной тест удержания горячей клавиши остановился на получении фокуса тестовым окном Проводника.
- В контрольном замере установленной сборки с открытыми настройками за 30 секунд простоя счётчик CPU процесса не вырос. Приватная память составила 124,2 МиБ, рабочий набор — 153,6 МиБ. Быстрый просмотр в трёхсекундном замере не запускал таймер ни для пробела, ни для боковой кнопки мыши.

## Повторение проверок

Сначала опубликуйте чистую Release-сборку по README. Для интерактивного теста закройте PixelThumbs в трее. Флаг `--desktop` создаёт и удаляет уникальный тестовый STL на рабочем столе. Флаг `--require-hidden` дополнительно проверяет подписи при включённом в Проводнике скрытии расширений известных типов. Пять путей к CAD и FBX можно передать в команду для дополнительной проверки миграции.

```powershell
$package = (Resolve-Path dist).Path
dotnet run --project tests/PixelThumbs.RenderChecks -c Release "-p:PixelThumbsPackage=$package" -- --worker --metrics
dotnet run --project tests/PixelThumbs.Registration.Tests -c Release
dotnet run --project tests/PixelThumbs.Registration.Tests -c Release -- --check-thumbnail-cache
dotnet run --project tests/PixelThumbs.PreviewChecks -c Release -- "$package\PixelThumbs.exe" --desktop
```

Проверки worker и нативного COM-хоста запускаются из копии публикации. Соберите проекты `PixelThumbs.WorkerChecks` и `PixelThumbs.Registration.Tests`, перенесите только их `.exe`, `.dll`, `.deps.json` и `.runtimeconfig.json` рядом с исполняемым файлом пакета. `PixelThumbs.WorkerChecks.exe` принимает каталог моделей, `PixelThumbs.Registration.Tests.exe --check-package` принимает тот же каталог с тестовыми файлами `cheese.stp`, `cheese.step`, `cheese.igs`, `cheese.iges`, `phong_cube.fbx` и `invalid.step`. Для двух пар расширений используются копии одной модели. [Модели F3D 4.0.1](https://github.com/f3d-app/f3d/tree/v4.0.1/testing/data)

Штатный интерфейс категории «Эскизы» использован согласно описанию Microsoft. [IEmptyVolumeCache2::InitializeEx](https://learn.microsoft.com/en-us/windows/win32/api/emptyvc/nf-emptyvc-iemptyvolumecache2-initializeex) · [IEmptyVolumeCache::Purge](https://learn.microsoft.com/en-us/windows/win32/api/emptyvc/nf-emptyvc-iemptyvolumecache-purge)
